# Testing Termeric

## Harvest command snapshot integrity

Raw-PTY regressions prove that retained commands keep quoted interior whitespace, line breaks and text beyond the 512-character display-caption limit, without sending a display ellipsis. Separate tests cover the 4-KiB UTF-8/capacity ceiling, upstream truncation, aggregate snapshot-budget eviction, both single-terminal and split-pane recording paths, locally truncated input refusal before focus, and a formerly enabled menu whose complete live text is later erased. Partial copy/Explain labels use the shared availability model; Explain's independent command/output truncation warnings are tested as pure string formatting without executing the action or invoking a provider. See [the command-text contract](integration-acceptance.md#exact-source-harvest-rerun).

## Exact-source Harvest rerun regression

The `harvest_rerun_*` tests use isolated raw PTYs that write received bytes to temporary capture files; no submitted command text is evaluated. They cover active broadcast with the source included/excluded, literal historical input despite aliases/completion, source focus, single-terminal ownership, armed and read-only refusal, stale/closed/closing targets, existing confirmations, and ordinary/synthetic-plugin destructive confirmation after focus/read-only/closure changes. Stream fences require new bytes before assertions. A separate closed destination test proves that an entire guarded batch is refused before its first user write. See [the routing contract](integration-acceptance.md#exact-source-harvest-rerun). Single-terminal and split-pane transcript fixtures also assert one input record per delivered rerun and no user-input record for protocol fences or refusals.

## Candidate-bound shell acceptance

The shared real-shell semantic probe sends one command only after a parsed input-ready prompt and the preceding command's completion, while continuing to answer terminal queries. It also requires the exact working directory at the first input-ready prompt and at the end. This replaces a startup input burst that Nushell 0.115.1 consumed incompletely during terminal negotiation. The paced default-config probe passes for all five supported shell families; Nushell's literal-percent `nushell_native_cwd_` test remains an explicitly ignored known failure. The user-disabled OSC 7 first-prompt regression now passes in the ordinary Unix suite with `nu` available (required under `TERMERIC_REQUIRE_NUSHELL_ACCEPTANCE=1`). Four `nushell_cwd_tests` helper cases independently cover the supplemental initial encoder's control/Unicode/URI handling, raw/encoded bounds, conditional output, and no duplicate on reentry. See [the reproductions and remaining work](osc-integration.md#nushell-native-producer-confirmed-gaps).

`nushell_launch_tests` verifies exact argv/environment preservation and no generated files for non-REPL/unknown modes, plus recognized REPL option arity, grouped short flags, equals values, and `--`. It does not execute server or plugin modes. `nushell_repl_launch_options_preserve_custom_config_and_command_lifecycle` executes three isolated real-Nushell PTY variants with custom configuration paths and checks the first cwd, unchanged rc bytes, multiline commands, and success/failure regions. It self-skips without `nu`, or fails when `TERMERIC_REQUIRE_NUSHELL_ACCEPTANCE=1` is set. See [launch eligibility](osc-integration.md#nushell-launch-eligibility).

`zsh_startup_tests` covers effective profile `ZDOTDIR`, unique environment values, nested unconsumed transport recovery, and legacy recursion prevention. Its real-Zsh subprocess test compares four isolated startup scenarios against plain Zsh, including child-shell directory inheritance and unchanged rc bytes. Nine further startup-chain scenarios compare `.zshenv`/`.zprofile`/`.zshrc` and native login/logout order, declaration scope, redirected/unset/non-exported paths, disabled `RCS`, readonly paths, and `nounset`. The separate `zsh_login_profile_emits_prompt_regions_with_nounset_when_available` real-PTY test checks the first prompt's cwd and multiline success/failure command regions after a user login profile enables `nounset`. Both self-skip without Zsh unless `TERMERIC_REQUIRE_ZSH_CWD_TESTS=1` is set. Optional global startup files are disabled in these fixtures, so their interaction is not accepted; see [the remaining startup-chain boundary](osc-integration.md#zsh-configuration-directory-handoff).

Its launch-routing cases additionally check grouped/long/named flags, `+` inversion, option order, `-s` operands, and end-of-options markers. Rejected command/script, startup-disabled, and unknown launches must leave argv and environment untouched without creating integration files. `zsh_reenabled_startup_and_stdin_arguments_preserve_prompt_regions` runs four real-PTY variants, requiring exact positional values for the `-s` case as well as rc loading, first-prompt cwd, and multiline success/failure regions. It self-skips without Zsh or fails under `TERMERIC_REQUIRE_ZSH_CWD_TESTS=1`.

`bash_launch_tests` checks exact pass-through and no generated files for non-rc/unknown modes (including POSIX environment), rc option order, stdin operands, and safe re-preparation. Seven real-Bash startup comparisons cover default, relative/absolute, dash-prefixed, shell-punctuation, empty, and missing rc paths with a PATH decoy and a nested child shell. Bash's non-PTY job-control warnings must match the native baseline; arbitrary stderr is not suppressed. `bash_custom_rc_and_stdin_arguments_preserve_prompt_regions` adds four isolated real-PTY variants for custom rc, multiple rc options/nounset, noediting, and exact stdin parameters, checking first-prompt cwd and complete command regions. Real-Bash tests self-skip when unavailable unless `TERMERIC_REQUIRE_SHELL_ACCEPTANCE=1` is set. See [the launch boundary](osc-integration.md#bash-launch-and-custom-rc-handling).

`bash_login_tests` adds routing/re-preparation and unprepared-source guards, fifteen native startup comparisons for profile selection/logout/ENV, and three more for history/export and inherited `inherit_errexit` state. Generated paths containing command-substitution punctuation must remain literal. The baseline and bootstrap must produce identical captured startup output and native non-PTY diagnostics, without changing user files. `bash_login_profiles_preserve_first_cwd_and_multiline_command_regions` adds three real-PTY cases for long/grouped/plus login flags and all three user-profile fallbacks. Login PTYs clear inherited environment and supply their temporary home, configuration, PATH, and history settings before launch preparation; the host's standard system profile still runs. First-prompt cwd, non-POSIX login identity, private-marker removal, and complete command regions are required. Tests require only the local Bash binary and self-skip if absent unless `TERMERIC_REQUIRE_SHELL_ACCEPTANCE=1` is set. See [the login evidence boundary](osc-integration.md#bash-login-shell-integration).

`fish_launch_tests` checks unchanged command/script, no-config/no-execute, utility, and unrecognized launches, plus exact option-value boundaries and insertion after user startup commands. Six native startup comparisons cover separate/attached commands, a final `--`, comments/punctuation, rc order, statuses 0/1/23, retained user hooks, and temporary-helper cleanup. These pass with isolated Fish 3.7.1 and 4.9.3 configurations. `fish_init_commands_and_launch_options_preserve_prompt_regions` adds four Fish 4.9.3 PTY variants for grouped/long flags, attached commands/end markers, and flag-looking diagnostic filenames. User prompt hooks must observe the expected startup order and installed integration; first-prompt cwd and complete multiline success/failure regions are required. These native tests self-skip without Fish unless `TERMERIC_REQUIRE_SHELL_ACCEPTANCE=1` is set. See [Fish's launch boundary](osc-integration.md#fish-launch-and-startup-command-handling).

`terminal::shell_integration::bash_cwd_tests` executes the generated Bash hook with isolated configuration, captures its bytes, and feeds only an in-memory terminal. It reproduces/prevents directory-to-title injection, round-trips UTF-8 and URI punctuation, checks every nonzero Unix pathname byte, verifies caller locale restoration, and exercises exact raw/encoded URI ceilings without losing prompt marks. No native window receives the synthetic protocol strings. Other shell emitters are not covered by those Bash results; see [cwd emission boundaries](osc-integration.md#working-directories).

`terminal::shell_integration::zsh_cwd_tests` independently runs the generated Zsh rc in an isolated real shell and feeds captured bytes into the in-memory terminal parser. Four regressions cover control-sequence injection, every nonzero Unix byte, UTF-8 and URI punctuation, exact raw/encoded URI limits, unchanged prompt markers, and caller locale/option restoration with default, KSH_ARRAYS, SH_WORD_SPLIT, and non-multibyte configurations. `terminal::shell_integration::fish_cwd_tests` adds five Unix real-shell regressions. The fixture checks unchanged locale and preserves/verifies Fish 3's OSC 133 prompt suffix; Fish 4's native OSC 133 producer is outside this non-interactive test. Both Fish 3.7.1 and 4.9.3 have passed these regressions using isolated, signature-verified Arch binaries; this is not user-configuration or desktop acceptance. Background mode is a required boolean on the wire and part of replay identity. Duplicate flags, window/new-tab use and incorrect wire types fail; flags after `--` stay literal. Real compositor focus/visual acceptance remains deferred; no provider is invoked.

## Linux software-renderer smoke lane

Set `TERMERIC_GPU_SMOKE=1` to require a headless WGPU adapter and submit a real render pass:

```bash
TERMERIC_GPU_SMOKE=1 cargo test -p termeric linux_headless_gpu_render_smoke_when_requested
```

CI should install Mesa's Vulkan software renderer (`mesa-vulkan-drivers` on Debian/Ubuntu), set `WGPU_BACKEND=vulkan`, and set `TERMERIC_GPU_SMOKE=1`. The test strictly requests a fallback adapter (llvmpipe); its absence is a hard failure rather than permission to hide the missing software path behind hardware. Set `TERMERIC_GPU_SMOKE_HARDWARE=1` on a real-GPU host to require a non-CPU adapter through the same visual subset. Without `TERMERIC_GPU_SMOKE=1`, the test prints why it was skipped. This lane includes 104 background-image pixel checks through the production upload/queue/clear paths: PNG/JPEG, four fits, three opacities, shifted/resized viewports, foreground rectangles, repeated frames, replacement, cache removal, and pipeline recreation. Every pixel is compared to an independent CPU inverse- mapping reference in the renderer's sRGB-encoded blending space. A color-fidelity check also requires theme colors, the clear color, and image pixels to present byte-exact through the view format chosen for an sRGB-only surface. Two GPU-free oracle regressions check rejection of missing or misplaced images and incorrect fit/opacity. It verifies CPU-RGBA release and retained texture counts, not actual driver allocation usage or full native UI layering; see [background evidence](background-images.md). The software lane also asserts that adapter diagnostics report a CPU device, so a changed WGPU selection policy cannot make the fallback lane pass on hardware. Its query-input glyph check includes command-palette, terminal-search, shortcut-filter, Settings-filter, and workspace-rename viewports with long ASCII and mixed-script text. It requires nonempty shaped geometry and every generated glyph vertex within the declared clip; this is not whole-panel pixel comparison or native IME acceptance.

Mesa hosts without a Vulkan software ICD can exercise the same strict CPU lane through surfaceless OpenGL. `LIBGL_ALWAYS_SOFTWARE` must be present before WGPU creates its instance so Mesa exposes llvmpipe instead of the installed GPU:

```bash
WGPU_BACKEND=gl EGL_PLATFORM=surfaceless LIBGL_ALWAYS_SOFTWARE=true \
TERMERIC_GPU_SMOKE=1 cargo test -p termeric \
  linux_headless_gpu_render_smoke_when_requested -- --nocapture
```

## Clippy policy

Strict Clippy is part of the default quality gate. The application crate has two narrow, documented exceptions: nested conditions are retained where UI dispatch priority or short Rust borrow scopes are clearer that way, and renderer builders may take explicit geometry/state parameters rather than hiding unrelated inputs inside generic parameter bags. New exceptions require a local rationale; broad lint-family suppression is not accepted.
